# ADR-0001: AIサポート機能における情報源の制限

- ステータス: 採用
- 日付: 2026-04-27
- 関係者: makimaki

## コンテキスト

StoryMapperはAIをサポート機能(要約、整理、検索)として組み込む。
このとき以下のリスクがある:

- AIが事前学習で得た作品知識を呼び出し、未読部分のネタバレを発生させる
- AIがWeb上の書評・Wikiから情報を引いてきて、原作者の意図を超えた解釈を表示する
- AIがユーザーの想像と異なる解釈・考察を押し付ける

これは本サービスの北極星「AIはユーザーの物語理解を尊重し、おせっかいをしない」
と直接矛盾する。技術的にどう徹底するかを決める必要がある。

## 決定

AIサポート機能で参照する情報源を whitelist 方式で制限する。

### 許可する情報源
1. ユーザーがStoryMapperに入力した情報(メモ、キャラクター情報、ラベル、シーン要約)
2. 公開書誌情報(タイトル、著者、出版年、ISBN、章タイトル)
3. 現在の会話セッション内でユーザーが入力した発話

### 禁止する情報源
1. AIモデルの事前学習データ由来の作品固有情報(プロット、結末、キャラ設定など)
2. Web検索結果(書評、Wiki、ファンサイトなど)
3. 他ユーザーが入力した情報(将来のソーシャル機能でも本人入力以外は使わない)

### 実装上の徹底ポイント
- プロンプト内では作品名を「この作品」と匿名化し、書誌メタ情報のみ渡す
- システムプロンプトで「以下のコンテキスト情報のみを参照し、事前知識は使うな」を明示
- 応答後バリデーション層で、入力に含まれない固有名詞が混入していないか検査
- AIに渡すデータは reading_progress.current_scene_id でフィルタ済みのものに限る

## 結果 (Consequences)

### ポジティブ
- ネタバレ流出リスクを最小化できる
- 著作権・作者意図との衝突を避けられる
- 「余計な情報を出さない」ことがブランドの差別化要素になる

### ネガティブ
- AIが提供できる情報の質・量が制限される(ユーザー入力が薄いと役に立たない)
- バリデーション層の実装・運用コストがかかる
- 作品名匿名化により、AI応答の文脈理解が弱まり、品質低下の可能性

## 検討した代替案

- **A. blacklist方式(禁止項目のみ列挙)**
  漏れリスクが大きい。「Wikiを使うな」と書いても、別のソースから類似情報が
  引かれれば防げない。ブランド毀損リスクが許容できないため不採用。

- **B. AIサポート機能自体を提供しない**
  ネタバレリスクは消えるが、StoryMapperの差別化要素が大きく損なわれる。
  ユーザー価値の源泉を失うため不採用。
