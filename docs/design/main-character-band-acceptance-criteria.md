# 主要キャラ帯 常時表示 — 合格基準（着手前固定）

- 作成日: 2026-07-08
- 改訂: 2026-07-10（設計フェーズ完了を反映。§0を確定へ更新、§2/§3を姿勢別に改訂、§5にチップ幅/横スクロール、§7にas-of正確性を追加）
- 対象機能: 読書ページ上の「主要キャラ帯 常時表示」（Week10 / recall課題対策）
- 位置づけ: **本実装に着手する前に固定する合格基準**（DP-8=A）。この基準を満たすまで機能を「完了」としない。
- **鉄則: 開発機（PC＋キーボード）での動作確認は「動作確認」であって「合格判定」ではない。合格判定は実機（実利用の保持姿勢・実場所）でのみ行う。**

## 1. 核心の合格ライン

> **読書位置を失わず、1タップで対象キャラの状態が読める。**

このラインを満たさないUIは、他がどれだけ良くても不合格とする。

**補助条項（§1直結・2026-07-10追加）**:
- [ ] **展開カードが「現在の読書行」を隠さない**。カードは下部からせり出すが、現在読んでいる行がカード上端より上に残る（または追加操作なしのスクロールで即復元できる）こと。recall中に読書位置を見失ったら本末転倒＝不合格。

## 2. 検証環境（この条件を満たさないテストは合格判定に使わない）

**姿勢別に分岐する（2026-07-10改訂）。** 分岐の主語は**デバイス名ではなく「現実の保持姿勢」**。デバイスは代理変数にすぎない。分岐の根拠は必ず下記の文書化した現実姿勢に紐づけること（＝難所を避ける逃げ道化の防止）。

共通:
- [ ] **実機**（開発機のブラウザ縮小・エミュレータ不可）
- [ ] **ポートレート（縦持ち）** ※プロファイルAで必須。Bは実利用の置き向きに従う
- [ ] **必ず本文がスクロールする状態**で行う（本文が短ければダミー高さを注入）
- [ ] 明るさ・振動など実利用に近い状況

### プロファイルA — スマホ・片手保持（厳格テストを維持）
実姿勢: 片手にスマホ、**もう片方の手は文庫本を保持**（電車の立位ではつり革の場合もある）。片手操作が現実的で、片手完結が本物の制約。
- [ ] **もう片方の手を物理的に塞ぐ**（実際に文庫本か水筒等を握った状態で行う）
- [ ] **実場所**: 電車（立位）または喫茶店。自宅デスク据え置きは不可

### プロファイルB — iPad mini・机置き据え置き（到達テストに置換）
実姿勢: 文庫本とiPad miniの両持ちは困難 → **喫茶店で机置き**、文庫本を読みつつ机上のiPad miniをぱっと参照。**両手が使える・据え置き**。
- [ ] **机上に据え置き**（手で保持しない）。両手可
- [ ] **実場所**: 喫茶店の机上（またはそれに準ずる据え置き環境）
- [ ] 「片手で右端が届かない」制約はこの姿勢では前提が当てはまらない。代わりに**机上リーチ内で全チップに無理なく届くか**を見る（§3-B）

## 3. 到達テスト（帯配置=下部stickyの到達性 ＋ 案C横スクロールの撃ち分け検証）

DP-4は下部stickyで確定済み。本節は**その到達性の最終確認**と、**案C（横スクロール）が片手で成立するか**の判定を行う。姿勢別。

### 3-A. スマホ・片手（厳格）
スマホを片手で保持し、**握りを組み替えずに**保持している手の親指だけで：
- [ ] 帯の**全5チップ**をタップできる（溢れる場合は横スクロールで手繰り寄せて押す）
- [ ] **親指1本で「横スクロール」と「タップ」を撃ち分けられる**（スクロールのつもりで誤ってチップが開く／タップのつもりでスクロールする、が起きない）
- [ ] 横スワイプが**本文の縦スクロールと競合しない**
- [ ] 状態カードを**開閉**できる（展開／**点灯中の同じチップを再タップ**で閉じる）
- [ ] 誤タップ（隣のチップ・別要素）が起きない

**フォールバック規定**: 上記の「横スクロール/タップ撃ち分け」が実機で安定して成立しない場合は、**案A（5番目＝最低頻度チップを親指ゾーン外に置き到達を諦める＝損失最小）にフォールバック**する。合否は実機判定のみ。PC縮小では判定しない。

### 3-B. iPad mini・据え置き（到達テスト）
iPad miniを机上に置き、据え置きのまま：
- [ ] 帯の**全5チップ**に机上リーチ内で無理なく届く（両手可）
- [ ] 横スクロールが必要な幅なら、スクロールとタップが据え置きでも撃ち分けられる
- [ ] カードの開閉・再タップ閉じが成立する

### バイアス除去（運用メモ）
- テストは**必ず本文がスクロールする状態**で行う（帯だけの固定画面では sticky 本来の挙動も到達も実利用と乖離）。
- 下部sticky条件は**ブラウザ下部クロム/OSジェスチャーバー/safe-area**、および**モバイルSafariのURLバー伸縮**に下端が食われると不当に低評価になる。safe-area-inset を考慮し、**配信文脈（PWAでなくブラウザタブならその状態）とchrome状態を固定**して計測する（測るたびに条件が揺れないように）。
- 案C横スクロールの**初期位置は rank1（先頭）**。端フェード/ピークで「続きがある」ことを可視化する。

## 4. タスクシナリオ（定量計測）

**シナリオ**: 「シーン15を読書中、シーン4で記録したキャラが再登場した。読書位置を失わずに、そのキャラの状態を確認する。」

計測項目（現行のモーダル動線と比較する）:
- [ ] **タップ数**: 状態が表示されるまで（合格ライン=**1タップ**）
- [ ] **所要秒数**: 再登場に気づいてから状態を読み終えるまで
- [ ] **読書位置の保持**: 確認後、元の読書位置に**追加操作なしで**戻れる（＝位置を失わない）
- [ ] **as-of の伝達**: 表示中の状態が**いつ時点の情報か**（`シーンN時点`）を読者が誤解なく認識できる。上記シナリオなら「シーン4時点の情報」と分かり、シーン15の現在地と混同しない
- [ ] 現行モーダル動線より、上記すべてで改善していること

## 5. タップ領域・チップ幅の物理基準

- [ ] チップの高さ **44px 以上**（タッチターゲット下限）
- [ ] チップ間の間隔が、塞がれた手の親指で誤タップしない程度に確保されている（現行 `gap-2`=8px は**片手誤タップを実測**して可否判断）
- [ ] **チップの名前は省略（truncation）しない**。帯で名前を省くと recall の目的（誰か即認識）を壊す。長名はチップが横に伸びる形で許容し、案Cの横スクロールに収容する（2026-07-10実機で長名の破綻なしを確認済み。幅ポリシーは設けない）
- [ ] 5チップが `max-w-2xl` 幅に収まる場合は全表示。溢れる場合は横スクロール（§3の撃ち分け・初期位置rank1・端フェードの要件を満たすこと）

---

## 6. 「参照 vs 書く」チェック（今回の目的からの逸脱防止）

- [ ] この帯は**読む（参照）専用**で、新たな「書く（入力・生成）」動線を増やしていない
- [ ] as-of の `シーンN時点` 表示は**既存データからの導出のみ**で、新たな書き込みを発生させない
- [ ] AI要約の生成ボタン・stale判定など「重い/書く」要素を帯に持ち込んでいない（要約はモーダルへ）
- [ ] 編集導線・「登場中」マーク等の書く操作を帯に載せていない（編集は既存 `/characters` モーダルへ。presence/rosterは別DP）
- [ ] 「ダイアログを閉じると状態が確認できなくなる」問題が解消されている（読書と参照が同一平面で共存）

---

## 7. データ健全性・描画堅牢性

- [ ] 帯に表示される状態が `scene order_key <= current_scene` の範囲に収まっている（第1層フィルタと一致）
- [ ] **as-of の N が由来シーンを正しく指す**（表示中の状態が実際に記録されたシーンの位置番号と一致。ズレると誤読を生む）
- [ ] `finished`（読了）モードで全件表示に切り替わる
- [ ] 他ユーザーの本のデータが混ざらない（RLS）
- [ ] **カード高さの有界化**: raw_memo が長い場合はカードに max-height＋内部スクロールを設け、下部占有が無制限に増えないこと（§1補助条項＝読書行を隠さない、と両立）
- [ ] **薄い/全nullの状態の描画定義**: 3欄も raw_memo も無いキャラをタップした時の表示が定義されている（空カード・「記録なし」等が意図通り）

## 判定フロー

1. PC で実装・動作確認（＝ここでは「合格」と言わない）
2. §2 の**姿勢別**環境を整える（プロファイルA/B）
3. §3-A で案C横スクロールの片手撃ち分けを判定（不成立なら案Aへフォールバック）、§3-B で据え置き到達を確認
4. §4・§5・§6・§7 を実機でチェック
5. §1 の核心ライン（補助条項含む）を含め全項目を満たして初めて「完了」とする

このドキュメントの各チェックを実機で通すまで、`feature` ブランチをマージしない。
