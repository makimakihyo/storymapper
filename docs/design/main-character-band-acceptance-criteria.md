# 主要キャラ帯 常時表示 — 合格基準（着手前固定）

- 作成日: 2026-07-08
- 対象機能: 読書ページ上の「主要キャラ帯 常時表示」（Week10 / recall課題対策）
- 位置づけ: **本実装に着手する前に固定する合格基準**（DP-8=A）。この基準を満たすまで機能を「完了」としない。
- **鉄則: 開発機（PC＋キーボード）での動作確認は「動作確認」であって「合格判定」ではない。合格判定は実機（タブレット縦持ち・片手・実場所）でのみ行う。**

---

## 0. 前提となる設計決定（確定済み）

| 項目 | 決定 |
|---|---|
| ランキング | 自動・登場頻度順（記録シーン数降順、同数は直近更新でタイブレーク） |
| 表示件数 | 上位5名 |
| 詳細表示 | タップでインライン展開（アコーディオン、単一オープン） |
| 帯の内容 | 構造化3欄（居場所/目的/所属）＋raw_memo。AI要約は載せない（既存モーダルへ逃がす） |
| データ取得元 | `latest_visible_character_states` ビュー（ネタバレフィルタ内蔵・RLS準拠） |
| **帯の配置** | **未確定（上部sticky / 下部sticky）→ 本基準の親指到達テストで決定** |

---

## 1. 核心の合格ライン（1行）

> **読書位置を失わず、1タップで対象キャラの状態が読める。**

このラインを満たさないUIは、他がどれだけ良くても不合格とする。

---

## 2. 検証環境（この条件を満たさないテストは合格判定に使わない）

- [ ] **実機タブレット**（開発機のブラウザ縮小・エミュレータ不可）
- [ ] **ポートレート（縦持ち）**
- [ ] **もう片方の手を物理的に塞ぐ**（実際に文庫本か水筒等を握った状態で行う）
- [ ] **実場所**: 電車（立位・片手はつり革or本）または喫茶店。自宅デスク据え置きは不可
- [ ] 明るさ・振動など実利用に近い状況（電車内を想定）

---

## 3. 親指到達テスト（＝DP-4「帯の上部/下部」を決める判定）

タブレットを片手で保持し、**握りを組み替えずに**保持している手の親指だけで：

- [ ] 帯の**全5チップ**をタップできる
- [ ] 状態カードを**開閉**できる（展開／再タップで閉じる）
- [ ] 誤タップ（隣のチップ・別要素）が起きない

**判定**: 上記を最も安定して満たす配置（上部sticky / 下部sticky）を採用する。両方試して比較すること。片方でもこのテストを通らない配置は不採用。

**バイアス除去（運用メモ）**:
- 上下の**試行順をカウンターバランス**する（上→下 と 下→上 を入れ替えて複数回）。常に同じ順だと慣れ・疲労のバイアスが判定に乗る。
- テストは**必ず本文がスクロールする状態**で行う（帯だけの固定画面では sticky 本来の挙動も親指到達も実利用と乖離する）。実データの本文が短い場合はダミー高さを注入してスクロールを発生させる。
- 下部sticky条件は**ブラウザ下部クロム/OSジェスチャーバー/safe-area** に下端が食われると不当に低評価になる。safe-area-inset を考慮し、**実際の配信文脈（PWAでなくブラウザタブならその状態）**で計測する。

---

## 4. タスクシナリオ（定量計測）

**シナリオ**: 「シーン15を読書中、シーン4で記録したキャラが再登場した。読書位置を失わずに、そのキャラの状態を確認する。」

計測項目（現行のモーダル動線と比較する）:

- [ ] **タップ数**: 状態が表示されるまで（合格ライン=**1タップ**）
- [ ] **所要秒数**: 再登場に気づいてから状態を読み終えるまで
- [ ] **読書位置の保持**: 確認後、元の読書位置に**追加操作なしで**戻れる（＝位置を失わない）
- [ ] 現行モーダル動線より、上記すべてで改善していること

---

## 5. タップ領域の物理基準

- [ ] チップの高さ **44px 以上**（タッチターゲット下限）
- [ ] チップ間の間隔が、塞がれた手の親指で誤タップしない程度に確保されている
- [ ] 5チップが `max-w-2xl` 幅に収まる（溢れる場合は横スクロール。ただし上位が最初からスクロール必須にならないこと）

---

## 6. 「参照 vs 書く」チェック（今回の目的からの逸脱防止）

- [ ] この帯は**読む（参照）専用**で、新たな「書く（入力・生成）」動線を増やしていない
- [ ] AI要約の生成ボタン・stale判定など「重い/書く」要素を帯に持ち込んでいない（要約はモーダルへ）
- [ ] 「ダイアログを閉じると状態が確認できなくなる」問題が解消されている（読書と参照が同一平面で共存）

---

## 7. ネタバレ・データ健全性

- [ ] 帯に表示される状態が `scene order_key <= current_scene` の範囲に収まっている（第1層フィルタと一致）
- [ ] `finished`（読了）モードで全件表示に切り替わる
- [ ] 他ユーザーの本のデータが混ざらない（RLS）

---

## 判定フロー

1. PC で実装・動作確認（＝ここでは「合格」と言わない）
2. §2 の環境を整える
3. §3 で帯の配置（DP-4）を決定
4. §4・§5・§6・§7 を実機でチェック
5. §1 の核心ラインを含め全項目を満たして初めて「完了」とする

このドキュメントの各チェックを実機で通すまで、`feature` ブランチをマージしない。
