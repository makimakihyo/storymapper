## 0. 方針と死守線

**方針B＝1入口化**: 読書ページに「書き留める」唯一の自由文入口を置き、**まず書く／分類は後段**。書く瞬間にユーザーへ分岐を発生させない。
**導入順序**: **案3（手動昇格）を先行**＝既存の抽出/プリフィル/upsert機構を再利用して最小改修で実機dogfoodへ。**案2（AI昇格提案）は後乗せ**＝実メモで的中率を計測してから重心を移す（本書のスコープ外）。

**死守線（崩したら不合格）**
1. **下層のデータ区別を温存**。分類を無くすのではなく「書く瞬間に分類させない＝後段でルーティング」。宛先の意味を保つ:
   - #2 人物の状態 = `character_states.raw_memo`（**1人1シーン1件・upsert上書き**・帯に出る）
   - #3a シーンの覚書 = `memos.body`（**append・何件でも**）
   - #3b しおり = `memos.is_bookmark`（本文なしで現在地）
2. **read側の帯を汚さない**（`latest_visible_character_states` ビュー・表示・as-of・登場頻度ランキングに影響を与えない）。**帯からの書き込み導線（案C）は今回スコープ外・保留論点**。
3. **DBスキーマ変更は最小**（しおり独立ボタンのための `body` 別扱いを除き、原則 migration を増やさない。初期スキーマは `body=''` のしおりを想定済み＝しおり自体に migration 不要）。

## 1. 決定事項（2026-07-15）

1. **scene_id ＝書いた時点のシーンにスナップショット**。覚書を「人物の状態へ送る」際、状態は**書いた瞬間のシーン**に紐づく（送るまでに読み進んでも観察時点を正とする）。→ 覚書の scene_id をフォームへ持ち込む。
2. **しおりは独立1タップボタンに分離**（1入口＝自由文専用、しおり＝別の専用ボタン・本文不要）。旧 M1 の しおり分離がそのまま活きる。
3. **文言は仮ラベルで進め、実機で調整**（「書き留める」「この人物の状態へ送る」等はプレースホルダ。迷い量に直結するため dogfood の文言テスト対象）。旧 M4 の改名は本方針に吸収＝仮ラベルで運用。

## 3. N1: 1入口「書き留める」

### 合格基準
- [ ] **N1-1. 読書ページに単一の自由文入口がある**（現状の「メモを追加」＝#3a と「登場人物」＝#2 の**書く入口が2つに割れている状態を解消**）。
- [ ] **N1-2. 入口を開くと textarea が主役**。保存は**無条件に覚書（`memos.body`, append）へ INSERT**。書く瞬間に「どこに書くか」の分岐が発生しない。
- [ ] **N1-3. 保存後、読書へ素早く戻れる**（自動クローズ＋reset）。二段階の退出を作らない。
- [ ] **N1-4. 既存のメモ作成の本文必須（`createMemoSchema.body.min(1)`）は維持**（覚書は本文ありが前提）。
- [ ] **N1-5. 片手タッチ到達**：入口ボタン・textarea・保存ボタンが画面下部の親指到達圏にあり、ソフトキーボード展開時も保存が隠れない。

## 4. N2: しおり独立ボタン（旧 M1）

### 合格基準
- [ ] **N2-1. 読書ページに独立した「しおり」ボタン**。ダイアログを開かず**1タップで現在シーンにしおり記録**（`body=''`, `is_bookmark=true`）。
- [ ] **N2-2. 本文を1文字も入力せずに打てる**。しおり用の別スキーマ（`createBookmarkSchema`：`scene_id` のみ）を切り、`createMemoSchema` の本文必須は緩めない。
- [ ] **N2-3. 同一シーンのしおりは最大1件**。2回目のタップはトグル解除（`body=''` かつ `is_bookmark=true` のレコードのみ削除。**本文ありレコードは対象外**＝初期スキーマの「昇格」運用と衝突させない）。ボタンが現在シーンのしおり有無を状態表示。
- [ ] **N2-4. `pending_memos` ビューの意味を壊さない**（`body=''` のしおりが整理待ちとして拾われる状態を維持）。
- [ ] **N2-5. しおりが `memo-list.tsx` 上で「しおり」として視認できる**（本文空でも一覧が壊れない）。

## 5. N3: 覚書 →「人物の状態へ送る」（案3の核）

### 現状の再利用資産
`character-state-form.tsx` は既に (a) 現在シーンの既存 state をプリフィル (b)「メモから抽出」で自由文→3欄 (c)「現在シーンで記録」で upsert、を持つ。**この機構を橋渡し先として丸ごと使う**（新規実装を最小化）。

### 合格基準
- [ ] **N3-1. 覚書カードに「この人物の状態へ送る」アクション**（`memo-list.tsx`）。タップ→キャラ選択。
- [ ] **N3-2. 選んだ自由文を `character-state-form` に prefill して開く**（`raw_memo` に覚書本文が入った状態）。以降は既存の「抽出→3欄→記録」に乗る。
- [ ] **N3-3. scene_id は覚書の scene をスナップショットして紐づく**（＝送信時の現在シーンではなく、覚書が書かれたシーン。フォームの記録先 scene をこの値で上書きする）。
- [ ] **N3-4. upsert（1人1シーン1件）の意味が保たれる**。送信先シーンに既存 state があれば上書き＝**その旨をユーザーが認識できる**（既存プリフィル表示、または「シーンNに既存の記録あり→上書き」の明示）。
- [ ] **N3-5. 送らなかった覚書は #3a に残る**（分類し損ね＝ロストしない。受け皿がデフォルトで存在）。元覚書は送信後も #3a に残す（#2へコピー、#3aから消さない）。

## 6. N4: 中断復帰の安全

### 合格基準
- [ ] **N4-1. 1入口で書きかけのまま本に目を戻し、数十秒後に戻る動線で、下書きが確認なく破棄されない**（読書は中断前提）。
- [ ] **N4-2. モーダル外タップ／iPad左端の戻りスワイプでの誤クローズで、未保存入力が無警告で消えない**。
- ※ 実装機構（確認ダイアログ／一時保持のどちらにするか）は**設計確定後に決める**。本人既決＝「データ永続化の作り込みはしない・確認ダイアログ寄り」（2026-07-13）を初期方針として引き継ぐ。旧 M2 ハンドオフ（`storymapper_week11_m2_handoff_draft.md`）の dirty/Radix 論点は、1入口の実装形が決まった段階で必要分だけ再利用。

## 9. 実機検証計画（タブレット＋タッチ＋片手＋ソフトキーボード）
- **片手到達**: 「書き留める」入口・「しおり」・保存ボタンが親指到達圏（画面下部）に収まるか。
- **ソフトキーボード被り**: textarea 入力時に保存ボタンが隠れないか（ボトムシート高さ追従）。
- **タップ領域**: キャラ選択チップ等が誤タップしない間隔（≒44px）か。
- **中断復帰**: 書きかけで本に目を戻し→戻る、で下書きが消えないか（N4）。
- **上書き認知**: N3-4 の既存プリフィル／上書き明示を見て「上書きされる」と実際に理解できたか（発話思考。PC では読めてしまうため必ずタッチで）。
